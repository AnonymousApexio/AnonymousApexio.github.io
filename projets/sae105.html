01En résumé

Objectif

Identifier les fichiers les plus volumineux d'un répertoire pour aider l'utilisateur à libérer de l'espace disque.

Ma contribution

Conception et développement de l'interface PyQt5 (camembert interactif, légendes paginées avec cases à cocher) et du générateur de script PowerShell de suppression.

Résultat

Une chaîne complète orchestrée par PowerShell : export JSON des 100 plus gros fichiers et suppression protégée par double confirmation.

02Le projet

Projet réalisé dans le cadre de la SAÉ 1.05 « Traitement des données » du BUT Réseaux & Télécommunications. L'objectif est de mettre en oevre une chaîne complète de traitement de données : collecte sur le système de fichiers, filtrage, export au format JSON, puis restitution graphique via une interface PyQt5.

L'outil s'adresse à un utilisateur souhaitant faire le tri dans un répertoire encombré (par exemple Downloads) et supprimer en connaissance de cause les fichiers les plus lourds.

  • Sélection interactive : choix du répertoire à analyser via une boîte de dialogue native (QFileDialog).
  • Parcours récursif : récupération de tous les fichiers et de leurs tailles sur l'ensemble de l'arborescence.
  • Tri et filtrage : conservation des fichiers >= 5 Mo, limités à 100 fichiers maximum.
  • Export JSON : sérialisation des résultats dans gros_fichiers.json.
  • Visualisation graphique : camembert représentant la répartition des tailles et légendes paginées (25 fichiers par page) avec cases à cocher.
  • Génération d'un script PowerShell de suppression des fichiers cochés, avec double confirmation.
  • Exécution immédiate du script de suppression depuis l'interface.

03Architecture

Le projet est organisé de façon modulaire, chaque composant graphique étant isolé dans un fichier dédié afin de faciliter la maintenance.

  • Run_Reporting_Tool.ps1 - orchestrateur PowerShell (point d'entrée), enchaîne les trois scripts Python en vérifiant chaque étape.
  • Script_1.py - sélection du répertoire via QFileDialog.getExistingDirectory, chemin renvoyé sur stdout.
  • Script_2.py - exploration récursive (rglob), tri décroissant, filtrage (≥ 5 Mo, 100 fichiers max) et export JSON indenté.
  • Script_3.py - interface PyQt5 : chargement du JSON, camembert, onglets de légendes, onglet IHM, génération et exécution du script de suppression.
  • Composants graphiques - Creation_Onglets.py (fenêtre principale), Creation_Camembert.py (QPieSeries), Creation_Legendes.py (lignes + cases à cocher), Creation_Boutons.py (bouton + champ texte).
  • docs/ - rapport PDF et présentation, requirements.txt - dépendances, LICENSE et README.md.

04Démarche

  1. Sélection du répertoire : ouverture d'une boîte de dialogue native et capture du chemin choisi par l'utilisateur.
  2. Analyse : parcours récursif du répertoire, collecte des couples [chemin, taille], tri décroissant, filtrage à 5 Mo et limitation à 100 fichiers, puis export dans gros_fichiers.json.
  3. Visualisation : chargement du JSON dans l'interface PyQt5, génération de couleurs aléatoires pour chaque fichier, construction d'une fenêtre à onglets (camembert, légendes paginées, IHM).
  4. Suppression sécurisée : génération de suppression_fichiers.ps1 à partir des fichiers cochés, double saisie manuelle de confirmation (OUI puis OUI), puis exécution via subprocess.

06Compétences BUT mobilisées (Apprentissage Critique)

AC13.01Utiliser un système informatique et ses outils

Exploitation du système de fichiers Windows (parcours récursif, chemins, tailles) via Python, usage de PowerShell comme orchestrateur de la chaîne, gestion de l'environnement Python (requirements.txt) et versionnage avec Git/GitHub.

AC13.02Lire, exécuter, corriger et modifier un programme

Lecture et reprise du code du binôme, exécution et débogage des trois scripts Python au fil de l'intégration, correction des erreurs de dialogue entre l'orchestrateur PowerShell et les scripts, modifications itératives des composants PyQt5.

AC13.03Traduire un algorithme, dans un langage et pour un environnement donné

Traduction en Python de l'algorithme de collecte (parcours récursif via rglob, tri décroissant par taille, filtrage à 5 Mo et 100 fichiers) et génération automatique du script PowerShell de suppression à partir des fichiers cochés dans l'IHM.

AC13.04Connaître l'architecture et les technologies d'un site Web

Non mobilisé directement par ce projet (application desktop PyQt5). Voir la SAÉ 2.03 pour la mise en oeuvre d'une architecture web complète (Django, Nginx, Gunicorn, MySQL).

AC13.05Choisir les mécanismes de gestion de données adaptés au développement de l'outil et argumenter ses choix

Choix du format JSON comme mécanisme d'échange entre l'analyse (Script 2) et la restitution graphique (Script 3) : format léger, lisible, standard et structuré, adapté à un volume plafonné à 100 fichiers — une base de données aurait été surdimensionnée pour ce besoin.

AC13.06S'intégrer dans un environnement propice au développement et au travail collaboratif

Travail en binôme (Clément & Ryan) avec une répartition claire des rôles : mon coéquipier sur la collecte et l'export, moi sur l'interface PyQt5 et les composants graphiques. La modularité du code (un fichier par composant) a facilité le travail en parallèle, avec un versionnage Git commun sur GitHub.

07Bilan

Ce que j'en retiens

Une première expérience complète d'une chaîne de traitement de données, de la collecte jusqu'à la restitution graphique. La séparation en composants m'a fait comprendre l'intérêt de la modularisation et le travail d'équipe de ce projet à été une lesson profitable pour moi.

Avec du recul

Nous avions eu 20/20 sur ce projet, mais avec le recule que j'ai actuellement, je pense que si je devais le refaire, je passerais plus de temps sur la partie documentation à l'origine ainsi que la sécurité du programme en question, particulièrement sur la partie logique métier.
